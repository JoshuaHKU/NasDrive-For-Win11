# NasDrive 0.3.0：群晖（Synology）服务类型与新托盘图标 设计方案

> 日期：2026-11-12　适用：NasDrive 0.3.0

## 第一部分：群晖（Synology）服务类型

### 1.1 需求

"新虚拟驱动器 → 服务类型"只显示三种：**WebDAV、NFS、群晖（Synology）**；删除其余未支持类型的文字（原副标题"Synology · QNAP · ASUSTOR · Nextcloud"）以及高级设置里的 WebDAV 厂商下拉框（nextcloud/owncloud/sharepoint/fastmail）。

### 1.2 "群晖"类型与 WebDAV/NFS 的区别

| | WebDAV | NFS | **群晖（新增）** |
|---|---|---|---|
| NAS 端需要开启 | WebDAV Server 套件 | NFS 服务 + 每个共享的 IP 规则 | **无需额外设置**（使用 DSM 自带的 File Station 接口，端口 5000/5001） |
| 认证 | 用户名/密码 | 无（按 IP） | DSM 用户名/密码 |
| 浏览共享 | 需手工填路径 | 列出导出 | **登录后列出该用户可见的全部共享文件夹** |
| 容量 | 群晖 WebDAV 不返回，显示假 1 PB | FSSTAT | **共享所在存储卷的真实容量** |
| 加密 | HTTPS | 无 | HTTPS |

这与 RaiDrive 的 "Synology" 类型一致：直接调用 DSM Web API（SYNO.FileStation.*）。

### 1.3 rclone 现状

rclone 的 70 余个后端中**没有** Synology/File Station 后端，因此与 NFS 一样，在 NasDrive 引擎内新增 rclone 后端 `synology`（`engine/backend/synology`），挂载、缓存、状态监控全部复用。

### 1.4 DSM File Station API 映射（实测 DSM 7：Auth v7、Upload v2-3，其余 v2，均为 `entry.cgi`）

| rclone 接口 | DSM API | 说明 |
|---|---|---|
| NewFs | `SYNO.API.Info` 查询路径/版本 → `SYNO.API.Auth login`（session=FileStation，format=sid） | 会话失效（106/107/119）时自动重新登录并重试 |
| List("") | `SYNO.FileStation.List list_share`（additional: time, volume_status） | 根目录即共享文件夹列表 |
| List(dir) | `SYNO.FileStation.List list`（offset/limit 分页，additional: size, time） | |
| NewObject | `SYNO.FileStation.List getinfo` | code 408 → 不存在 |
| Open | `SYNO.FileStation.Download`（GET，带 Range） | 服务器忽略 Range 时客户端跳过前导字节 |
| Put/Update | `SYNO.FileStation.Upload`（multipart 流式，overwrite=true，create_parents=true，mtime 毫秒） | 不缓存整文件，边读边传 |
| Mkdir | `SYNO.FileStation.CreateFolder`（force_parent=true） | 已存在视为成功 |
| Rmdir | 先 List 确认为空 → `SYNO.FileStation.Delete`（同步 delete 方法） | 非空 → ErrorDirectoryNotEmpty |
| Remove | `SYNO.FileStation.Delete` | |
| Move（同目录改名） | `SYNO.FileStation.Rename` | |
| Move/DirMove（跨目录） | `SYNO.FileStation.CopyMove start`（remove_src=true）+ `status` 轮询，名字不同时再 Rename | 服务端完成，不经客户端 |
| About | `list_share` 的 volume_status（freespace/totalspace） | 取根路径所在共享 |
| SetModTime | 不支持（File Station 无此接口）→ 上传时携带 mtime | Precision = 1 s |
| Shutdown | `SYNO.API.Auth logout` | |

连接字符串：

```
:synology,url='https://nas:5001',user='bob',pass='<obscured>',override.no_check_certificate='true':/共享/子目录
```

HTTP 客户端使用 rclone 的 `fshttp`，因此超时、忽略证书、每驱动器代理等设置与 WebDAV 完全一致。

### 1.4.1 两步验证（2FA）

实测：用户的 DSM 账户启用了两步验证，登录返回 403（需要验证码）。因此必须支持 2FA，做法与 RaiDrive 相同：

1. 首次连接/测试时引擎返回 `syno_2fa`，界面弹出"输入 6 位验证码"对话框。
2. 界面调用新接口 `nasdrive/synologin {fs, otp}`：以 `otp_code` + `enable_device_token=yes` + `device_name=NasDrive-<电脑名>` 登录，DSM 返回设备令牌 `did`（等同于网页登录时勾选"在此设备上不再询问"）。
3. `did` 保存在 Windows 凭据管理器（`NasDrive:syno-device:<驱动器ID>`），之后的连接字符串带 `device_id='<obscured>'`，DSM 不再要求验证码。
4. 用户在 DSM 中撤销该设备后，再次连接会重新弹出验证码对话框。

### 1.4.2 真机联调中发现的 DSM 7 行为（已处理）

| 现象 | 处理 |
|---|---|
| 登录需要 2FA 时，`error.errors` 是对象而非文档中的数组 | 延迟解析，只有数组时才取子错误码 |
| Auth **v7** 用验证码登录成功但**不返回设备令牌** `did` | 改用 Auth **v6**（DSM 6.2/7.x 均支持，Home Assistant 的群晖集成同样使用 v6） |
| 设备令牌与登录时的 `device_name` 绑定 | 所有登录统一使用 `NasDrive-<电脑名>`；取得令牌后立即用它登录一次作校验 |
| `list_share` 带 `limit=-1` 时 DSM 返回 **HTTP 502** | 去掉 limit（默认即返回全部） |
| 参数加引号（`"/share"`）或不加都可接受 | 统一按 DSM 网页端的 JSON 格式发送 |
| 2FA 登录接口未应用"忽略证书"等每驱动器设置 | rc 接口内按 `fs.NewFs` 的方式套用 `override.*` |

真机端到端（Win11 + DSM 7，账户启用 2FA）：登录、列共享、挂载、真实容量 6857 GB、中文文件读写改删、64 MB 上传 6.2 s、在线探测、卸载，全部通过。

### 1.5 错误分类

| DSM 错误码 | errorCode | 界面提示 |
|---|---|---|
| 400（登录） | `unauthorized` | 用户名或密码错误 |
| 401/402（登录） | `forbidden` | 账户已停用或无权限 |
| 403（登录） | `syno_2fa` | 需要两步验证码 → 弹出输入框 |
| 404（登录） | `syno_2fa_bad` | 验证码错误或已过期 |
| 406（登录） | `syno_2fa_enforce` | 管理员要求该账户启用两步验证，请先在 DSM 网页中完成设置 |
| 407（登录） | `syno_blocked` | 本机 IP 已被 DSM 自动封锁 |
| 105 / 407 | `forbidden` | 无权访问 |
| 408 | `not_found` | 路径不存在 |
| 416 / 415 | `syno_nospace` | 空间不足/超出配额 |
| 网络/TLS | 与 WebDAV 相同 | |

### 1.6 界面

- 服务类型三个按钮：WebDAV ｜ NFS ｜ 群晖（Synology）；不再显示其它产品名。
- 群晖：HTTPS 开关 + 地址 + 端口（默认 5001，关 HTTPS 为 5000）、用户名/密码、路径；新增 **"列出共享"** 按钮：用当前账号登录后列出共享文件夹，点击即填入路径。
- 粘贴 `https://nas:5001/...` 时若端口为 5000/5001 自动识别为群晖。
- 新增 rc 接口 `nasdrive/listdirs {fs, dir}`：列出某个连接下的子目录（群晖用它列共享）。

### 1.7 测试

- 单元/一致性：Go 内置的**模拟 DSM 服务器**（httptest，实现上表全部 API 与错误码）上运行 rclone `fstests`。
- 真机：在 Win11（192.168.1.20）上，从 Windows 凭据管理器读取 NAS 账号（Claude 不接触密码），运行 `test-mount.ps1 -Protocol synology`：登录、列共享、挂载、读写中文文件、改名、上传、删除、容量、卸载。

## 第二部分：托盘图标

### 2.1 现状问题

当前托盘图标在运行时用 GDI+ 画在 32×32 位图上：图形只占画布约 60%，线条 2 px；Windows 托盘实际显示 16×16（100% 缩放）到 32×32（200%），被缩小后只剩一个模糊的色块。

### 2.2 设计

- **造型**：圆角方块"磁贴"铺满画布（≈94%），上面是白色 NAS 机箱（两块硬盘托架 + 指示灯），下方一条网络连线（竖线 + 横线）——表达"网络上的 NAS 盘"。
- **状态用磁贴颜色表达**（远比小角标清晰）：
  - 蓝色 `#1677FF→#0B5CD6`：有驱动器已连接
  - 灰色 `#8A8F98→#6B7079`：无连接
  - 琥珀色 `#F5A623→#D98A00`：有驱动器离线/出错
- **按尺寸单独绘制**（16、20、24、32、40、48、64、256 px），小尺寸减少细节、线宽对齐像素，避免缩放模糊；托盘按当前 DPI 取系统小图标尺寸（`SM_CXSMICON`）选用最合适的一张。
- 应用程序图标（exe、窗口、安装包）同步换成蓝色版本，风格统一。
- 生成工具：`scripts/genicon`（Go，抗锯齿矢量绘制），输出 `NasDrive.ico` 与三种状态的托盘 `.ico`，并输出 PNG 预览。
